# TowerDefenseGame

## 프로젝트 개요

`TowerDefenseGame`은 고박사 유튜브의 타워 디펜스 게임 제작 영상을 바탕으로 구현하고 있는 Unity 프로젝트입니다.

영상의 구현을 그대로 따라가는 것에 그치지 않고, 제작 과정에서 발생하는 의존성과 책임을 분석한 뒤 제가 생각하는 게임플레이 구조에 맞게 리팩터링하는 것을 목표로 합니다.

프로젝트를 진행하면서 기능을 빠르게 구현하는 방식과, 이후 확장하기 쉬운 구조 사이의 균형을 확인하고 있습니다.

---

## 리팩터링 기준

이 프로젝트의 구조는 책임을 분배하기 위해 처음부터 많은 객체를 만드는 것을 목표로 하지 않습니다.

먼저 작은 구조로 플레이를 구현하고, 기능이 복잡해졌을 때 기존 책임을 적절한 객체로 쉽게 이동할 수 있도록 구성합니다.

완성된 구조를 미리 만들기보다 실제 개발 과정에서 드러나는 의존성과 책임의 경계를 기준으로 확장합니다.

각 기능은 가능한 한 상위 객체 없이도 독립적으로 동작하도록 구성합니다.

객체가 자신이 몰라도 되는 외부 계층에 요청해야 할 때는 Handler를 통해 구체적인 구현과 플레이 구조에 대한 의존성을 제한합니다.

---

## 기본 구조

```text
SceneRoot
    │
    ▼
Director
    │
    ▼
Flow
    │
 ┌──┴───────────────┐
 ▼                  ▼
Actor              Viewer
 │                  │
 ▼                  ▼
Module              View
```

* `SceneRoot`는 Scene에서 사용되는 객체의 초기화와 조립을 담당합니다.
* `Director`는 여러 Flow의 실행 순서와 생명주기를 조율합니다.
* `Flow`는 여러 객체 사이의 실행 흐름과 게임 규칙을 구성합니다.
* `Actor`는 하나의 Unity 런타임 오브젝트를 대표하고 내부 Module을 연결합니다.
* `Module`은 Actor 내부의 구체적인 상태와 기능을 담당합니다.
* `Viewer`는 화면에 표시할 상태와 표현을 관리합니다.
* `View`는 실제 UI 컴포넌트와 사용자 입력을 담당합니다.

# 핵심 원칙

> 이 구조의 목적은 책임을 분배하기 위해 객체를 많이 만드는 것이 아닙니다.
>
> 작은 구조로 플레이를 먼저 완성하고, 복잡해진 책임을 적절한 위치로 쉽게 이동할 수 있도록 만드는 것이 목적입니다.

```text
객체 내부의 상태와 기능
→ Module

System에서 사용되는 Actor의 역할
→ RoleModule

역할의 등록과 조회
→ System

하나의 Unity 오브젝트 구성
→ Actor

화면과 연출
→ Viewer

객체 사이의 플레이 규칙
→ Flow

여러 Flow의 순서와 전환
→ Director

Scene 초기화와 조립
→ SceneRoot
```

처음부터 책임을 모두 나누지 않습니다.

먼저 플레이를 구현하고, 실제로 드러난 경계를 따라 책임을 이동하며 확장합니다.
